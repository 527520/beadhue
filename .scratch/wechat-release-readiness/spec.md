# 微信接入前的 Web 发布门禁修复

Status: ready-for-agent
基线：main 9a95b456。独立于原 feat/wechat-personal 工作区，避免将生产准备和小程序实现混成一个大 PR。

用户要求代理完成所有可自行处理的接入和验收工作。生产当前运行 v0.6.0；小程序后端尚未发布。现有 main CI 与依赖审计失败，必须如实处理，不能绕过检查后直接部署。

## 范围

- 修复有已发布补丁的生产依赖安全问题；采用最小兼容升级，保留所有审计门禁。
- 建立 Firefox 重新裁剪后「保存中…」超时的实际反馈循环，找到可复现根因后再修复，保证本地设计、原图和 CAS 规则。
- 无补丁或不能重现的问题保留明确状态和证据，不虚构成功。
- 不在此票引入小程序 UI、登录协议、功能增减、生产切流或数据库迁移。

## 验收

- 锁文件与实际依赖版本对应；生产审计按现有 CI 范围执行，准确记录退出状态及未关闭项。
- 类型检查、构建与受影响邮件/配置测试通过；有代码修复时，真实回归应先失败后通过。
- 不增加超时、跳过测试、忽略漏洞或伪造真机证据来通过门禁。
- 通过 Standards/Spec 审查后提交独立可评审变更；未满足的正式发布条件继续阻塞。

## 规范与技能

遵守 AGENTS.md、CONTEXT.md 及相关存储/部署 ADR。沿用 ask-matt 的独立任务组织；依赖/API 文档使用 Context7。Firefox 故障使用 diagnosing-bugs，实现遵循 ponytail 的最小改动原则。此票不改变视觉；既定 frontend-design、awesome-design-md 的 Web 基准继续有效。
