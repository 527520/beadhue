## 修复与反馈闭环

- 原生 WXSS 拒绝 `.stack > * + *`：改为 Flex 纵向 16px 间距，并消除直接 Field 的重复 margin。
- 属性选择器 `[disabled]` 不生效：组件添加 disabled 类，保留原生 disabled 负责交互。
- 无效 app.json 相册 scope 声明移除；相册操作仍按平台 API 申请权限。
- `getImageInfo` 返回内置图片相对路径，子页误解析为 creation/entry/assets：保留输入的资源根路径；路径测试先失败后通过。
- 原生 Worker 把重复色板对象引用判为 circular reference：双向消息 JSON 深拷贝；真实生成消息回归先失败后通过，随后模拟器生成成功。
- 原生 Function 构造探测可通过但结果不能执行：Zod 在业务 Schema 构造前设 jitless；同一失败项目 JSON 已在 Node 校验有效，并补运行时回归。
- Canvas 首次节点与图层未准备好：等 useReady、查询发起页、有限重试和动画帧绘制；隐藏页面卸载旧预览与编辑 Canvas，显示时恢复。完整链路截图检测在修复前为 0，最终为 32,915 个彩色像素。微信内部合成原因未作确定性断言。
- 图片解码改为每次独立离屏 Canvas，避免异步任务共用 DOM 解码节点。

SDK 的 slider.slideTo 调用卡住，改为真实 change 事件；SDK touchstart 不保留 Canvas 局部 x/y，画笔自动化通过原生页面 eh 入口派发与原生点击一致的事件。原生点击另行验证成功。自动化事件测试不能替代真机手势。

代码检查：`weapp:typecheck`、`weapp:test`（12 文件 33 项）、`weapp:build` 和包体预算通过。主包 1,194,516 字节，creation 138,638，account 24,357，export 23,734，workers 1,815,510；所有包低于 1.8 MiB 工程预算。历史默认 Web 全量测试状态仍见 verification.md；本轮未重跑整套 Web 回归。

## 复跑

自动化 SDK 安装在仓库外，避免新增产品依赖：

```sh
npm install --prefix /tmp/beadhue-weapp-acceptance --package-lock=false miniprogram-automator@0.12.1
/Applications/wechatwebdevtools.app/Contents/MacOS/cli auto --project /Users/wuqian/project/doupu/doupu/apps/weapp --auto-port 9420
node .scratch/wechat-miniprogram/devtools-acceptance.cjs
```

若 SDK 安装目录不同，设置 `WEAPP_AUTOMATOR_MODULE` 为其模块绝对路径。每次复跑创建唯一验收名称，不删除旧数据；禁止把测试数据同步到生产账号。
