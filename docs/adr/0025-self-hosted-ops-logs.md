# ADR-0025: 自建运行日志、慢查询与连接池可观测

- Status: accepted
- Date: 2026-09-17
- Related: ADR-0004（限流：同样把平台自身状态当作需要可读的事实）, ADR-0020（评论内容安全留痕）, D50

## Context

站点上线后，「出错了吗、什么时候、哪个账号、哪个地址、做了什么、报了什么」只有一条获取路径：登录服务器看 stdout。
容器日志随部署滚动，用户报障时给的截图里只有一个 500 和一句「服务器内部错误」；`requestId` 虽然已经写进响应体与审计表，
但错误本身没有落到任何可查询的地方。慢查询与连接池水位同样只能靠 SSH 上去看 `pg_stat_activity`。

需求（用户第 15 条）明确要求：管理后台里能看到错误日志、SQL 日志与慢查询（含完整调用链）、连接池信息，
并明确「接入开源方案也可以」。因此本 ADR 记录的是**取舍**，而不是实现细节。

三条边界在此之前就已经由其他决策定下，本票不得突破：

1. 平台不记录请求正文、评论正文、邮箱、令牌与图纸内容（隐私政策第三节、第五节、第六节）；
2. 匿名分析（ADR-0014）已经证明「去标识化 + 明确目的 + 有限保留期」是平台可接受的采集方式；
3. 部署是单机 Docker Compose（`docker-compose.prod.yml`），运维人力只有一个，没有 Grafana / Loki / Sentry 的运维预算。

## Decision

1. **自建，不引第三方可观测栈。** 两张表 + 一个后台模块，全部在现有 Next.js 进程与现有 PostgreSQL 内完成：
   - `system_logs`：错误与事件流水（来源、事件名、级别、账号、掩码地址、requestId、路径、状态码、耗时、错误码、消息、堆栈、上下文）；
   - `slow_queries`：只记超过阈值的语句（语句文本、耗时、行数、`route → service → db` 调用链）；
   - 连接池读数不落表：直接读 `globalThis` 上注册的 `pg` 池实例（`totalCount` / `idleCount` / `waitingCount` / `max`），
     加上 `pg_stat_activity` 汇总与 `pg_database_size(current_database())`。
2. **只采慢查询，不做全量 SQL 日志。** 阈值默认 500 ms（`SLOW_QUERY_MS`，设为 `0` 停用），由 `pool.query` 包装层计时；
   只存语句文本，**绝不存参数值**（drizzle 发的是 `$n` 占位符，保持原样）；日志表自身的写入不参与计时，避免「写慢查询」再触发慢查询。
3. **不启用 `pg_stat_statements`。** 它需要 `shared_preload_libraries` + 重启实例，收益（全量语句聚合）与本票「只看慢查询」的目标重叠；
   后台只显示「未启用」状态与启用步骤，不假装能采全量 SQL。
4. **掩码边界写死在写入路径上。** 网络地址只以掩码形式入库：IPv4 保留前三段（末段清零），IPv6 只保留前 48 位（其余清零），
   无法识别时记为 `unknown`；`local`（无反代头）原样保留，它本身不是地址。掩码在 `withApiErrors` 建上下文时执行，
   任何调用点拿不到原始 IP 可写。
5. **保留期：错误与事件 30 天（`SYSLOG_RETENTION_DAYS`），慢查询 14 天（`SLOW_QUERY_RETENTION_DAYS`）。**
   由 `src/instrumentation.ts` 的每日清理删除，与限流窗口、原图清理同一批任务；隐私政策第九节写明「最长保留 30 天，仅管理员可见」。
6. **权限沿用 `audit:read`。** 错误行里带调用堆栈与内部路径，只有管理员能读；页面与四个 API 各自校验一次
   （`/admin/logs` 页 `forbidden()`，`/api/admin/logs*` 走 `requireApiActor`）。
7. **写入是尽力而为的旁路，且有上限。** 写日志失败只打 stdout，绝不抛回请求处理；每进程每分钟最多
   `SYSLOG_MAX_ROWS_PER_MINUTE`（默认 200）行，超出的按分钟汇总成一条 `syslog.suppressed` 说明行，不做静默丢弃；
   生产路径下拿不到数据库句柄（库不可达）时直接放弃写入。
8. **4xx / 429 一律不落库。** 那是攻击者可控的量，写库等于把攻击放大成写放大；只有 5xx、显式安全事件
   （`recordSecurityEvent`，供邮件预算耗尽、登录锁定等调用）与浏览器错误边界上报（每 IP 每小时 60 次）会落库。
9. **跨副本状态放 `globalThis`。** webpack 会把 instrumentation 与各路由打包成互相独立的模块副本，
   连接池必须注册到 `globalThis`（键 `__doupu_prod_pool__`），后台「数据库」页与 instrumentation 才能读到同一个池；
   这与 PGlite 回退库（`src/lib/auth/db.ts`）用的是同一个套路。

## Consequences

- 用户报障时，后台可以直接按 `request_id` 检索出「这一次请求的全部记录」，不需要 SSH；
  浏览器端错误边界上报的请求由服务端补 requestId 与掩码 IP，因此 500 与前端报错能落到同一条链上。
- 引入了一张会持续增长的事实表：写入放大受每分钟上限约束，容量受保留期约束（默认 30/14 天），
  清理任务失败只记 stdout，不影响应用。
- 掩码后的地址可用于「同一网段反复出错」这类聚合，但**不能用于定位单个自然人**；这是刻意的隐私边界，
  换来的是隐私政策里可以如实写明的一句话，而不是「我们不记录网络地址」的谎言。
- 慢查询的调用链依赖调用点在关键边界手动 `pushSpan`（路由入口、后台查询服务、数据库健康读数）。
  没有 `pushSpan` 的路径只会少几环面包屑，不会漏掉语句本身——可观测性的完整性是渐进的，不是全有全无。
- 后台多了一个需要长期维护的模块（页面 + 4 个 API + 写入器 + 采集层），以及一条护栏：
  新增字段时必须同时判断是否属于禁止落库的五类内容（`redact()` 的键名清单）。

## Rejected alternatives

- **外部 SaaS / 开源栈（Sentry、Grafana + Loki、OTel Collector）**：需求允许，但代价与收益不匹配。
  单机部署下多一个常驻组件（Loki 至少 +1 容器 +1 卷 + 采集配置），Sentry 还要把堆栈（含内部路径与可能的用户数据）
  发到第三方；两者都要新的凭证、新的数据出境路径与新的失败模式，而本票要回答的问题只有六个字段。
  自建的代价是一张表与一个页面，且数据不出库。
- **全量 SQL 日志**：写放大与隐私风险都不可接受——参数值一旦落库，等于把用户内容抄进日志表；
  只存 `$n` 占位符又无法回答「哪条语句慢」，所以只留阈值触发的慢查询。
- **启用 `pg_stat_statements`**：需要改 `postgresql.conf` 并重启实例，且它的聚合视图无法还原「这一次请求」的调用链；
  用一个需要重启的扩展换一张看不了上下文的表，不如直接采集。
- **记录完整 IP（或 HMAC 后的 IP）**：完整 IP 能精确定位到人，超出「防滥用与排障」的必要范围；
  HMAC 需要额外的密钥管理，且一旦密钥泄露等于没掩码。掩码是能同时满足「够用」与「可如实告知」的那一档。
- **把错误直接写进审计表（`admin_audit_logs`）**：审计回答的是「谁改了什么」，要求写入前必须有操作者与理由；
  运行日志回答的是「系统发生了什么」，包含匿名请求与渲染错误。两者混表会让审计出现大量无操作者的行，
  也会让审计的「只增不改、只记管理动作」这一语义失效。
