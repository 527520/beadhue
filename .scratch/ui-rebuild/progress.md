## 自主巡检（Loop Engineering）

主会话用 `loop` 技能自唤醒：常驻进程 `tools/loop-watch.py 1200` 盯住本会话全部子代理记录（含新派发的），任一结束即输出 `AGENT_LOOP_WAKE_r15`，另每 20 分钟输出一次心跳；进程不退出，醒来的那一轮被截断也不影响下一次唤醒。每次唤醒：按下面的恢复方法巡检 → 处理（续跑 / 验收 / 合并 / 派发）→ 更新本表。只有进程不在了才需要重启它（进程号见 `tools/.loop-pids`）。

并行策略：票 03 完成后（E2E 端口可配置），04、05、06、07、10 可在隔离工作树并行（最多 3 个同时），逐个合并回主分支；合并由主会话做，冲突集中在 `src/messages/zh-CN.ts`、`src/app/theme.css` 的 `@source`、`tests/unit/uiGuardrails.test.ts` 的清单。

## 恢复方法（主会话被截断后）

1. 看本表与各票头的 `Completion:`；`git log --oneline` 看已提交的票。
2. 「进行中」的票：用 Task `resume` 发一句「继续」试探；返回「currently running」说明仍在跑，不要重复派发。
3. 子代理的完成通知可能不送达：读 `agent-transcripts/<会话>/subagents/<id>.jsonl` 末尾的最终回报与 `turn_ended` 状态。
4. 票 02 完成后：在主工作区 `git merge --no-ff <它的分支>`，解决冲突，跑 typecheck / lint / 受影响测试，再派发票 03。
